#
# 周末流水账：一天搭了三样小东西，关掉了一个坑

> 记录 10 月 18 日。没有大成果，都是一些"做完之后世界安静了一点点"的小事。

## 起因

不是因为我有多想做项目。

是因为这两天在群里看别人聊天，经常有这种感觉：别人随口一句话，我得回去查半小时；别人聊的缩写我一个都听不懂。这种落差攒久了会变成一种压力——不是"我要变强"的那种，是"我好像被落下了"的那种。

所以我给自己定了个很土的目标：**别再靠"刷到什么算什么"，改成主动去找、并且把找到的东西存下来。**

一天下来做了三件事。

---

## 一、让群聊自己长出日报

### 想解决什么

我常待的几个群里，其实每天都在掉有用的东西：一个冷门命令、一个活动、一个别人踩过的坑。但聊天记录翻起来太痛苦——往上划两百条，找到一句"哦那个啊，用 xx 就行"。

于是我想：能不能让机器替我盯着，每天晚上给我一份"今天群里值得记的三件事"。

### 做成了什么

现在每天晚上定时跑一次，第二天我能看到一份摘要：谁说了什么、为什么值得记、原文在哪。

中间的数据流大概是这样：

代码块

```
群里有人说话
   ↓
本地脚本接住 → 一行一条存成文本文件
   ↓
到点自动挑重点 → 生成摘要
```

存的时候用的是 **JSONL**——你可以理解成"一行一条记录"的文本文件。它的好处是不用装数据库、用记事本就能打开、出问题一眼看得出哪一行坏了。

### 踩了三个坑（这部分才是有价值的）

**坑一：日期用错了时区**

脚本按日期分文件，一开始我让它用"世界统一时间"生成文件名。结果：**半夜 12 点到早上 8 点之间的消息，会被写进前一天的文件里。**

因为中国比世界统一时间快 8 小时，我们的凌晨，在那边还是"昨天"。

这个坑今天没暴露——我第一次采集是在早上 8 点半之后。但要是哪天凌晨聊天，数据就会莫名其妙跑到昨天的文件里，而且很难发现。

**教训**：凡是涉及"今天是几号"，一定要问自己一句：**这是谁的时间？**

**坑二：断线重连会写重复**

连接偶尔会断，断了会自动重连。重连之后，如果同一条消息又被推过来一次，文件里就会多出一行一模一样的。

修法是加一个"**已经见过的消息编号**"名单：来一条先查名单，见过就丢掉。而且这个名单在启动时要先读一遍当天已有的文件——不然重启之后名单清零，照样重复。

**坑三：数据被备注污染了**

我给每个群配了个中文名字，方便在日志里看。结果我顺手在名字后面加了句备注：

代码块

```
"工作群（核心情报源）"
```

然后这一整串——**包括括号里的备注**——被当成群名写进了每一条数据里。

单看没什么，但当你想按群名统计的时候，就会得到两个"看起来像但不是同一个"的名字。

**教训**：**给机器看的东西，永远只放纯数据；给人看的备注，另外放一个变量。** 这两个混在一起，早晚要重新洗一遍历史数据。

### 现在的状态

代码块

```
数据：110 条，消息编号零重复
群名：只剩两个干净的
运行：还在跑
```

## 二、给自己定了个"每天三篇"的计划

### 想解决什么

不是缺信息，是**不知道去哪看、看什么、看了记不住**。

### 设计思路

我给自己定了几条硬规矩：

1. **中文为主**。英文源可以进，但必须配中文摘要，不然我根本不会点。
2. **每天三篇，三块轮着来**：算法、工程、AI。
3. **不要只存链接**。链接会失效、会要登录、会被墙。所以每篇都存两段：
    - 一段"速览卡"：出处 + 为什么给我看 + 三个要点 + 难度和阅读时长
    - 一段**洗干净的正文**：去掉导航栏、广告、评论区，只留内容

这样做的原因是：**我以后想问这篇的细节，不用再点开网页。**

### 第一期出来的真实反馈

三篇我都想看。但有一篇讲的东西我完全不会——跳表和红黑树，我连名字都是第一次认真看。

比这个更扎心的是另一件事：

> **我发现自己已经几乎不看长文了。**

不是看不懂，是**坐不住**。刷短视频、刷帖子，一段超过三百字就手滑往下划。这个习惯养了几年，现在反过来卡住了我自己。

所以"每天三篇"这件事，真正的难点不是找到文章，是**让我自己重新读得下去**。这一点我还在想办法。

## 三、把要一直跑的东西搬到了云上

### 想解决什么

我电脑一关，那些"应该一直在线"的东西就断了。而我又不可能 24 小时不关机。

### 做了什么

用学生身份领了一台很小的云主机（2 核 2G，够用），系统是 Ubuntu。

真正花时间的不是"开通"，是**开门的方式**。

新机器默认用密码登录。但公网上每天都有大量脚本在挨个试密码——这就等于把钥匙藏在门口脚垫下面。所以我做了四件事：

1. **换成密钥登录**：本地生成一对钥匙，公钥放到服务器上，以后只认"拿着私钥的人"。
2. **关掉密码登录**：改完配置，用命令检查语法没错，再重启服务。
3. **换掉默认端口**：默认那个端口是全网扫描的第一目标，换一个不常用的。
4. **开防火墙**：只放行我自己要用的端口，其余一律拒绝。

### 最爽的一刻

改完之后，我故意做了一次测试：**不带密钥、只用密码去连**。

结果：

代码块

```
Permission denied
```

被拒绝了。

**那个"被拒绝"的瞬间，才是这次配置真正成功的证据。** 不是"我能连上"，而是"别人进不来"。

### 一个必须记住的点

云平台上有单独一套"**安全组**"，服务器自己还有一个"**防火墙**"。这是**两道门**。

很多人改完服务器里的设置，发现还是连不上，就是因为**只开了一道门**。改端口的时候，两边都得动。

## 今天学到的三件事

**1. 落盘比记忆靠谱**

所有结论写进文件，换设备、换对话、隔一个月回来都还在。靠"记得上次说过"是最脆的。

**2. 每一步都要有一条"验证命令"**

不然你永远分不清：是这件事做对了，还是它刚好没报错。

**3. 别完全相信 AI 的结论，包括它很自信的时候**

今天我至少被带偏三次：把一个真实存在的东西说成假的、把"我没查到"当成"不存在"、把还没跑起来的东西说成"已经跑好了"。每次都是回头翻原始数据才拉回来。

AI 很擅长给答案，但**它给的答案和"事实"之间，始终隔着一个"你去核对了吗"**。
AI总结的，不过真的好晚了啦，我才不要自己写。
